# MCP сервер для AI-агентов

MCP сервер даёт AI-агенту (например, ассистенту в сервисе чатов) инструменты для работы
с задачами, заявками и сотрудниками: создание и декомпозиция задач, формирование пула задач
по заявке, подбор исполнителей с учётом опыта и загрузки, обсуждение в комментариях.

## Подключение

| Параметр  | Значение                                              |
|-----------|-------------------------------------------------------|
| Транспорт | Streamable HTTP (stateless)                           |
| Endpoint  | `http://<host>:8001/mcp/` (обратите внимание на `/`)  |
| Auth      | `Authorization: Bearer <access token>`                |

Токен - обычный access-токен пользователя из `POST /api/v1/auth/login`. Агент действует
**от имени этого пользователя** и со всеми его ограничениями: работают те же доменные
проверки прав, что и в REST API, а действия попадают в историю и уведомления.
Refresh-токены и отозванные токены не принимаются. Сервер доступен только сотрудникам:
для клиентов компоненты скрыты и вызовы запрещены.

Сервис чатов должен передавать актуальный токен пользователя в каждом запросе
(access-токен живёт 15 минут, обновление - на стороне сервиса чатов).

```json
{
  "mcpServers": {
    "diodesk": {
      "url": "http://localhost:8001/mcp/",
      "headers": {"Authorization": "Bearer <access token>"}
    }
  }
}
```

```python
from fastmcp import Client

async with Client("http://localhost:8001/mcp/", auth=access_token) as client:
    card = await client.call_tool("get_task", {"task": "TASK-001"})
```

## Компоненты

Задачи и заявки везде принимаются по номеру (`TASK-001`, `INT-26-00000012`) или UUID,
пользователи - по UUID или `"me"`.

### Инструменты

| Группа        | Инструменты                                                                                     |
|---------------|-------------------------------------------------------------------------------------------------|
| Пользователи  | `get_current_user`, `search_users`                                                              |
| Задачи        | `get_task`, `search_tasks`, `create_task`, `update_task`, `change_task_status`, `assign_task`, `request_task_review`, `review_task` |
| Планирование  | `create_tasks_from_ticket`, `decompose_task`, `get_team_workload`, `get_user_expertise`, `suggest_assignees`, `suggest_tasks_for_user` |
| Заявки        | `get_ticket`, `search_tickets`, `assign_ticket`                                                 |
| Комментарии   | `list_ticket_comments`, `add_ticket_comment`, `list_task_comments`, `add_task_comment`          |

Изменяющие инструменты помечены MCP-аннотациями (`readOnlyHint`, `idempotentHint`),
по которым клиент может запрашивать подтверждение пользователя.

### Ресурсы

- `tasks://workflow` - статусы задачи, допустимые переходы (вычисляются из workflow) и правила;
- `tasks://{reference}` - карточка задачи;
- `tickets://{reference}` - карточка заявки с пулом задач.

### Промпты (готовые сценарии)

`plan_ticket_tasks`, `summarize_ticket`, `plan_task_assignment`, `plan_task_decomposition`,
`daily_digest`, `review_team_workload`.

## Подбор исполнителей и задач

Логика - в `src/tasks/domain/assignment.py`, она простая и объяснимая:

- **Опыт** строится по выполненным задачам за период (по умолчанию 180 дней):
  частота тегов и ключевых слов из названий и описаний, точность оценок (факт / оценка).
- **Загрузка** - открытые задачи и активные заявки: остаток оценок
  + 4 ч за неоценённую задачу + 2 ч за активную заявку.
  Доступность = 40 / (40 + загрузка).
- **Кандидат в исполнители** = 0.6 × соответствие опыта + 0.4 × доступность.
- **Задача для сотрудника** = 0.75 × соответствие опыта + 0.25 × срочность (приоритет, срок).

Каждая рекомендация содержит обоснование (`reasons`), чтобы человек мог проверить выбор.
Качество подбора напрямую зависит от тегов на задачах.

## Ошибки

Доменные ошибки возвращаются агенту как понятные сообщения
(`NOT_ALLOWED_STATUS_TRANSITION: ...`, `PERMISSION_DENIED: ...`), прочие - маскируются.

## Разработка

```bash
# тестовые сотрудники (пароль у всех - test), создаются и при старте приложения
python -m cli create-test-users
# демо-история задач, текущая загрузка, свободные задачи и заявка для декомпозиции
python -m cli seed-demo-data
```

Структура: инфраструктура и точка сборки - `src/mcp/`, компоненты - в модулях
(`src/iam/mcp`, `src/tasks/mcp`, `src/tickets/mcp`). Новый модуль добавляет свой
`create_server()` и монтируется в `src/mcp/server.py`.
